# evolve propose — system-driven proposal (design chart)

S10 of the v0.5 plan. The biggest v0.5 item: close the core gap where
Evolution is manual (the agent hand-writes cue/lesson) by having the
SYSTEM assemble the evidence pack a proposer needs. Read down to `## Log`.

## Position

harness2's improver sessions receive a built evidence context
(`context.build`: rollouts, pool, library, decisions) plus dimension
templates, and propose tree edits with one retry and fallback. Regulus
has no model-calling core: the deterministic half transfers (evidence
assembly + validation + candidate schema), the authoring half stays
with the agent/guardian until a model loop exists. This chart designs
only the deterministic half — no new model calls, no new runtime.

## Acceptance

### Scenario: propose assembles the evidence pack

- Given a task with traces, receipts, an admitted lesson, and budget entries
- When `regulus evolve propose --task <t> --domain <d>` runs
- Then it prints one pack with: trace fingerprints of recent sessions (labeled by session id — traces are session-scoped), receipt summaries for the task (gate, verdict, duration), the domain INDEX, and recent evolution decisions for the task — each section labeled, empty sections marked `(none)` instead of omitted

### Scenario: the pack validates its inputs

- Given a task with no receipts (evidence gate)
- When propose runs
- Then it exits 1 naming the missing evidence, records nothing, and the usage line documents the evidence contract

### Scenario: the candidate schema is explicit

- Given a complete pack
- When propose runs
- Then it appends a candidate template with empty `dimension:`, `component:`, `edit:`, `rationale:` fields plus the allowed value lists, so the authoring half (agent/guardian) fills a validated shape instead of free prose

## Design

- New `evolve` command group (`evolve propose` first; `compose` already
  exists under `probe`, `admit` stays in reflect/library — no renames).
- Evidence sources (all read-only reuse): `trace.List` across sessions
  filtered by task? Traces are session-scoped, not task-scoped — pack
  includes recent sessions' fingerprints (cap: last 3 sessions with
  entries) labeled by session; receipts via evidence dir glob for the
  task slug; INDEX via `library.IndexFile` read; decisions via
  `budget.Show` filtered to the task (cap: last 5).
- Output is human/machine-readable markdown to stdout; exit 0 pack,
  1 refusal (no receipts / unknown domain with no INDEX and no
  sessions), 2 usage.
- No budget record (assembly is free; only reflect/probe consume).
- Cross-project: no repo-specific paths; works wherever the core runs.
