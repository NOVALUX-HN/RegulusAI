The gap analysis (P0-P4) turned into this Chart: each pending item
becomes a scenario with its verification. Read down to `## Log`.

## Acceptance

### Scenario: the Almanac completes its design promises

- Given observations with pin events, relations and provenance
- When `regulus memory pin|unpin|relate|export` run
- Then pins reorder search and surface in context, relations record supersedes/conflicts with validated ids, search annotates git distance when provenance carries a git head, the context names the project from its git remote, and export writes the committed team bundle

### Scenario: surface edits become mechanical

- Given a lesson that should change the harness surface
- When `regulus surface propose` targets a whitelisted surface file and `regulus surface apply --guardian` executes it
- Then the proposal is refused for targets outside the surface whitelist, the budget counts the proposal against the daily cap, the apply appends the content with the guardian recorded, and the ledger shows the story

### Scenario: lessons reach the agent without being asked

- Given admitted lessons in the Almanac
- When an OpenCode session assembles its context
- Then the plugin injects the newest lessons DATA-framed, and a `/regulus-verify` command dispatches the guardian protocol in one step

### Scenario: the gauntlet runs everywhere and once

- Given regulus.json on any platform
- When the gauntlet runs
- Then no command hardcodes a platform binary, the test suite executes once feeding both layers 4 and 5, status reports whether gremlins is available, and CI runs the gauntlet on push

### Scenario: charts scaffold themselves and dependencies get scanned

- Given `regulus chart init <name>` and the govulncheck gate
- When a newcomer starts a Chart and the gauntlet runs
- Then the scaffold passes spec check with a valid example scenario, chart list reports every Chart with its scenario count, and govulncheck scans the dependencies as the layer-8 gate

### Scenario: the boundary proves itself live

- Given the plugin compiled against the real OpenCode V2 runtime
- When a headless OpenCode process loads it
- Then the tools and commands register, and the pending lesson candidate — its evidence audited — is admitted by the guardian, closing the last deferred live step of v1
